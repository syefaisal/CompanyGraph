# Design Decisions

**Project:** CogniGraph — Meridian Property Group Knowledge Graph  
**Purpose:** Documents every architectural decision, the alternatives considered, the rationale, and the alignment with the RealPage Lead AI Engineer role requirements.

---

## 1. Technical Strategy & Architecture

| # | Decision | Alternatives Considered | Choice Made | Rationale | JD Alignment |
|---|----------|------------------------|-------------|-----------|--------------|
| 1.1 | **Primary data store** | Relational DB (Postgres), Document store (MongoDB), Vector DB (Pinecone/Weaviate) | **Neo4j graph database** | Relationships between people, products, customers, workflows, and decisions are first-class citizens — not joins or embeddings. Cypher enables multi-hop traversal (e.g. Person → Decision → Customer) in a single expressive query that would require multiple round-trips or post-processing in other stores. | *"Data and retrieval architecture — knowledge graphs"* |
| 1.2 | **LLM provider** | OpenAI GPT-4o, Google Gemini, open-source (Llama) | **Anthropic Claude (Sonnet + Haiku)** | Prompt caching API reduces repeated-context cost by ~10×. Tool-use / function-calling is first-class. Strong instruction-following for structured graph reasoning. Haiku provides a cost-optimised tier for simple lookups. | *"Model selection strategy (Google vs. OpenAI, small vs. large models)"* |
| 1.3 | **Query architecture** | Single model size for all queries | **Three-tier model routing: direct → Haiku → Sonnet** | List/count queries need zero LLM cost (~30 ms). Simple entity lookups fit Haiku. Complex multi-hop reasoning (compliance traces, risk chains) needs Sonnet. Routing by complexity indicator keywords and question length. | *"Model selection strategy — small vs. large models; model routing, distillation, caching strategies"* |
| 1.4 | **Agentic pattern** | Single-turn QA (dump graph → ask Claude), LangChain agents, LangGraph | **Native Anthropic tool-calling loop** | Avoids framework lock-in (LangChain, LangGraph). Direct SDK control over each turn means transparent observability — every tool call, result, and reasoning step is emitted as a typed SSE event. The loop is simple enough to own entirely: `while stop_reason == "tool_use": execute → append → next turn`. | *"Multi-agent and workflow orchestration patterns — responder/thinker pattern, tool calling, agentic frameworks"* |
| 1.5 | **Streaming strategy** | Polling (client requests completion), WebSocket, long-poll | **Server-Sent Events (SSE) with typed event schema** | SSE is unidirectional (server → client), which matches the LLM streaming use case perfectly. Typed events (`thinking`, `tool_call`, `tool_result`, `text`, `done`) let the UI render the agent's reasoning trace in real time — a differentiating UX pattern for agentic systems. | *"Evaluate and introduce — real-time streaming infrastructures"* |
| 1.6 | **Document ingestion** | Manual data entry, pre-structured JSON import, SQL ETL | **Claude tool-use extraction pipeline** (`doc_to_graph.py`) | Plain-text company briefs already exist in every organisation's wiki. Using `tool_choice: {type: "tool"}` forces exactly one structured tool call — no hallucination risk, no regex parsing. The same extraction schema works for any prose-heavy internal document. | *"Reusable RAG pipelines and ingestion frameworks"* |
| 1.7 | **MCP server** | REST-only API, GraphQL API, custom Claude plugin | **Model Context Protocol (FastMCP)** | MCP is the emerging standard for connecting AI systems to external tools and data. Exposes the graph as 11 typed tools consumable by any MCP-compatible client (Claude Desktop, Claude Code, future agents). Reuses the same `graph.py` layer — no duplication. | *"Advanced agent frameworks — Agents SDK, emerging tool standards"* |

## 2. Data & Retrieval Architecture

| # | Decision | Alternatives Considered | Choice Made | Rationale | JD Alignment |
|---|----------|------------------------|-------------|-----------|--------------|
| 2.1 | **Retrieval strategy for `/query`** | Per-query RAG (chunk documents, embed, retrieve top-k), full-text search | **Full graph serialised into a cached system prompt** | At this scale (30 nodes, 71 edges), the entire graph fits in ~2,000 tokens. Serialising it once and caching the system prompt block means every subsequent query within 5 minutes pays ~0.30/1M input tokens instead of $3/1M. No retrieval errors from incorrect chunk selection. | *"Data and retrieval architecture — semantic caching, RAG"* |
| 2.2 | **Search mechanism** | Exact substring match (`CONTAINS` in Cypher), dense vector embeddings (OpenAI, Voyage), full-text index | **BM25 lexical ranking** (pure Python, no extra dependencies) | BM25 correctly weights IDF — rare terms like "GDPR" or "Fair Housing" score higher than common words. Falls back to substring search on zero results. Demonstrates hybrid retrieval thinking without adding a vector database dependency at this scale. Easily upgradeable to dense + sparse fusion when the graph grows. | *"Hybrid search, vector databases, retrieval optimization techniques"* |
| 2.3 | **Graph schema design** | Flat property bags, document-per-entity, entity-attribute-value | **Typed node labels + directed relationship types** | Five distinct node labels (Person, Product, Customer, Workflow, Decision) with 8 relationship types (`WORKS_ON`, `OWNS`, `MADE`, `AFFECTS`, `INVOLVES`, `DEPENDS_ON`, `PRODUCES`, `USES`) enables structural queries impossible in flat stores: path-finding, blast-radius analysis, dependency chains, single-point-of-failure detection. | *"Knowledge graphs — relationships are first-class"* |
| 2.4 | **Prompt caching implementation** | No caching (pay full input cost per query), application-layer response cache (Redis) | **Anthropic ephemeral prompt caching on two system blocks** | The system prompt and full graph context are marked `cache_control: ephemeral`. Anthropic caches them for 5 minutes server-side. First query in a session pays full cost; every subsequent query hits the cache at ~10× lower input cost. Cache hit rate is tracked in `/metrics`. | *"Semantic caching; model routing, distillation, and caching strategies"* |
| 2.5 | **Domain data** | Generic B2B SaaS (original Nexus Corp), e-commerce, finance | **PropTech — Meridian Property Group** (property management SaaS) | Directly mirrors RealPage's business domain. Entities map to real PropTech concerns: lease compliance (`Fair Housing Audit`), regulatory decisions (`GDPR and CCPA Overhaul`), vendor risk (`Outsource Vendor Network`), product analytics (`OwnerInsight`). Demonstrates domain literacy, not just generic AI architecture. | *"Identify high-value AI use cases aligned with PropTech domain needs"* |

## 3. Platformization & Reusable Capabilities

| # | Decision | Alternatives Considered | Choice Made | Rationale | JD Alignment |
|---|----------|------------------------|-------------|-----------|--------------|
| 3.1 | **Graph access layer** | Direct Cypher in each endpoint, ORM (neomodel), separate microservice | **Single `graph.py` module shared by API, MCP server, seed, eval, and tests** | One source of truth for all graph operations. Adding a new capability (e.g. `hybrid_search_nodes`) automatically benefits `/search`, `/query`, the agent tools, and the MCP server simultaneously. No duplicated Cypher across files. | *"Modular reusable coding practices for agentic back-end processes"* |
| 3.2 | **Agent tool definitions** | Inline tool schemas in each endpoint, external JSON config, framework-generated | **Declarative tool schema list (`AGENT_TOOLS`) + single `_execute_agent_tool()` dispatcher** | Tool definitions are pure Python dictionaries — versionable, testable, and readable without running the server. The dispatcher is a single function covering all 5 tools, making it straightforward to add tools or change behaviour without touching the agent loop. | *"Reusable RAG pipelines; modular reusable coding practices"* |
| 3.3 | **API framework** | Flask, Django REST Framework, raw ASGI | **FastAPI** | Async-native (matches async Anthropic SDK streams). Auto-generates OpenAPI docs at `/docs`. Pydantic request validation. `StreamingResponse` is first-class. Minimal boilerplate — the entire API is one file. | *"Designing and operating distributed, cloud-native systems"* |
| 3.4 | **Frontend stack** | Vue, plain HTML/JS, Next.js, Streamlit | **React 18 + Vite + TypeScript + Tailwind** | Matches the production standard for AI copilot UIs. TypeScript enforces contracts between the SSE event schema and the React state. Vite proxy eliminates CORS config in dev. Force-directed graph (`react-force-graph-2d`) provides an immediate visual of the knowledge graph structure. | *"Common UI components and design patterns for AI copilots and agents"* |
| 3.5 | **Model selection visibility** | No UI feedback on routing, log-only observability | **Routing Decision Badge + Observe tab** | Every response shows a colour-coded pill with the tier (Direct/Haiku/Sonnet) and exact reason (`'compliance' detected`, `simple lookup`, `budget limit reached`). The Observe tab shows a live bar chart of tier distribution, token breakdown, session cost, and a LangSmith trace feed — auto-refreshing every 10 s. `_route_explanation()` generates the reason and travels in the `done` SSE event as `route_reason`. `GET /langsmith/runs` is server-side to keep the API key out of the browser. | *"Model selection strategy — communicating complex AI concepts to non-technical partners; observability, logging"* |
| 3.6 | **Infrastructure** | Managed cloud Neo4j (Aura), local SQLite graph simulation, in-memory graph | **Neo4j in Docker (`docker compose up -d`)** | Portable — anyone can run the full stack with one command. Neo4j 5.x community edition includes the full Cypher engine and APOC procedures. Swap to a cloud-hosted instance in production with a one-line env var change. Demonstrates **containerization** fluency. | *"Containerization and orchestration (Docker, Kubernetes)"* |

## 4. Evaluation, Governance & Responsible AI

| # | Decision | Alternatives Considered | Choice Made | Rationale | JD Alignment |
|---|----------|------------------------|-------------|-----------|--------------|
| 4.0 | **LLM tracing platform** | Custom logging, no tracing, OpenTelemetry, Arize Phoenix, Helicone | **LangSmith** (`langsmith>=0.1.0`, optional via env vars) | `wrap_anthropic` auto-traces every `messages.create()` call in the agent loop (inputs, outputs, token usage, latency). `@traceable` decorators on `route_query` and `_execute_agent_tool` capture routing decisions and tool I/O as child spans. `_run_agent_traced()` posts the full agent run tree (chain → LLM turns → tool calls) as a single named trace. **Activation requires all three vars:** `LANGSMITH_API_KEY` (credentials), `LANGSMITH_PROJECT` (destination), and `LANGSMITH_TRACING_V2=true` (master switch — decorators and `wrap_anthropic` are unconditional no-ops without it). API restart required after `.env` changes. Verified: one agent query produces 5 LangSmith runs (3 `llm` + 2 `tool`). | *"AI experiment tracking and evaluation frameworks (LangSmith Evals); observability, logging, and incident response for AI systems"* |
| 4.1 | **Evaluation framework** | Manual spot-checking, LangSmith tracing, no eval | **`eval.py` — offline eval harness with entity recall scoring** | 8 PropTech test cases covering workflow ownership, compliance traces, customer-360, decision impact, path-finding, risk analysis, and hybrid search quality. Scores **entity recall** (fraction of expected entities mentioned), latency, and model routing per case. Pass threshold is 0.6 recall. Runnable as `python eval.py` or `python eval.py --agent`. | *"Define robust evaluation frameworks — offline metrics for relevance; model and retrieval evaluation"* |
| 4.2 | **Human-in-the-loop feedback** | No feedback mechanism, external tool (Argilla, LabelStudio) | **In-UI thumbs-up / flag + review sidebar** | Every AI response has thumbs-up (approve) and thumbs-down (flag with comment) controls. Flagged responses accumulate in a Review tab with the reviewer's comment. Demonstrates the **human evaluation workflow** pattern for complex or sensitive outputs — essential for PropTech compliance responses. | *"Human evaluation workflows for complex or sensitive tasks"* |
| 4.3 | **Compliance domain representation** | Generic business decisions | **GDPR, CCPA, Fair Housing Audit as first-class graph entities** | Regulatory decisions (`GDPR and CCPA Compliance Overhaul`) and compliance workflows (`Fair Housing Audit`) are nodes in the graph with `AFFECTS` relationships to products and workflows. Impact traces reveal which products and customers are in scope for a regulatory change. Models responsible AI thinking by making compliance consequences queryable. | *"PII handling; GDPR-like requirements; content safety, bias and fairness — designing AI products in domains with regulatory constraints"* |
| 4.4 | **Test architecture** | No tests, pytest only for unit, manual API testing | **4-tier test suite: unit (BM25 + routing) + integration (graph + API) + LLM (marked, opt-in)** | Unit tests require no external services and run in < 0.5 s. Integration tests validate the full stack against live Neo4j and the HTTP API. LLM tests are marked `@pytest.mark.llm` and skipped by default — they call Claude and cost money. 176 tests, all passing. Demonstrates **test standards and code quality** leadership. | *"Observability, logging, and incident response; guide architectural decisions and code quality"* |
| 4.5 | **Seed data integrity validation** | Trust the seed script ran correctly | **`TestSeedDataIntegrity` class in test suite** | 10 assertions verify that key PropTech relationships are correctly loaded: Rachel Torres owns Lease Renewal, GDPR affects LeaseTrack and TenantPay, LegacyPortal is deprecated, Sunstone uses 3+ products. Catches data quality issues before they reach the LLM. | *"Proactively identify and mitigate technical risks related to data quality"* |

## 5. Performance, Reliability & Cost Management

| # | Decision | Alternatives Considered | Choice Made | Rationale | JD Alignment |
|---|----------|------------------------|-------------|-----------|--------------|
| 5.1 | **Observability** | External APM (Datadog, New Relic), logging to stdout only, no monitoring | **In-process `/metrics` endpoint** tracking query counts, latency, tokens (input/cached/output), cache hit rate, model routing distribution, and estimated cost | Real-time visibility into every dimension that matters for AI cost management — without a paid external tool. The metrics are updated per-query and available instantly via `GET /metrics`. Demonstrates the mindset of **SLAs/SLOs for key AI services**. | *"Observability, logging, and incident response for AI systems; latency, uptime, error budgets"* |
| 5.2 | **Direct answer short-circuit** | Always call an LLM, even for trivial queries | **`_try_direct_answer()` bypasses the LLM for list/count queries** | "List all workflows" returns in ~30 ms at zero token cost. "How many products" reads a graph stat and formats the answer inline. Demonstrates the discipline of **not defaulting to LLM** when a deterministic path exists — directly reducing cost and latency for predictable query patterns. | *"Right-sizing infrastructure; model routing, distillation, and caching strategies; cost management"* |
| 5.3 | **Agent loop guard** | Unlimited iterations, fixed iteration count, external timeout | **Max 8 iterations with explicit error event on overflow** | Prevents runaway API cost if a question causes Claude to loop. 8 iterations is sufficient for the most complex queries (the GDPR compliance trace uses 8 tool calls). The `done` event always includes `tool_calls` count so the client can surface it. | *"SLAs/SLOs; proactively identify and mitigate technical risks related to scalability"* |
| 5.4 | **Cost estimation in metrics** | No cost tracking, exact billing API integration | **Approximate cost formula in `/metrics`** based on public Anthropic pricing | `((input - cached) × $3 + cached × $0.30 + output × $15) / 1,000,000`. Not exact (doesn't account for model mix within a session) but directionally correct and immediately useful for a demo or cost review. Demonstrates **data-driven tradeoffs between speed, quality, and cost**. | *"Lead performance and cost optimization; right-sizing infrastructure; build-vs-buy decisions"* |
| 5.5 | **Error handling in SSE streams** | Silent failure, HTTP 500 on any error, crash the stream | **Typed `error` event emitted into the SSE stream; `errors` counter in `/metrics`** | The stream stays open and delivers a JSON `{type: "error", content: "..."}` event rather than dropping the connection. The UI can render the error inline. The `/metrics` counter lets operators know if errors are accumulating without grepping logs. | *"Incident response for AI systems; reliability"* |
| 5.6 | **Build vs. buy for BM25** | Add `rank-bm25` package, use Elasticsearch, use pgvector | **BM25 implemented in ~35 lines of pure Python** | No new dependency. The full algorithm (IDF weighting, term frequency normalisation, document-length normalisation) fits in `graph.py` alongside the rest of the data layer. Avoids infrastructure complexity while demonstrating the underlying retrieval science. Upgrade path to a dedicated vector store is clear. | *"Build-vs-buy decisions; retrieval optimization techniques"* |

## 6. AI SDLC Conformance

The AI Software Development Lifecycle (AI SDLC) extends the traditional SDLC with stages specific to AI/ML systems: data engineering, model/prompt development, retrieval architecture, evaluation, responsible AI governance, and continuous feedback loops. This section maps each SDLC phase to the current project's implementation and identifies gaps with recommendations.

### 6.1 Phase Coverage — What the Project Implements

| SDLC Phase | Phase Description | Project Implementation | Evidence in Codebase |
|------------|------------------|----------------------|---------------------|
| **1. Discovery & Requirements** | Define the problem, use cases, success metrics, and feasibility before building | PropTech domain chosen to mirror real RealPage concerns. Six use cases defined as sample questions, each mapped to explicit JD requirements. Success criteria: entity recall ≥ 0.6, 8/8 eval cases passing. | `USER_GUIDE.md` (architecture matrix), `eval.py` (PASS_THRESHOLD), `VIDEO_SCRIPT.md` (JD coverage map) |
| **2. Data Engineering** | Source, validate, version, and govern the training/retrieval data | Plain-text source document (`nexus_corp_brief.md`) extracted by Claude into a typed graph schema. Neo4j uniqueness constraints enforce data integrity. Seed script clears and reloads deterministically. Seed data integrity validated by a dedicated test class. | `seed.py`, `doc_to_graph.py`, `graph.py` (constraints), `tests/test_integration_graph.py::TestSeedDataIntegrity` |
| **3. Prompt Development** | Design, version, and manage system prompts and agent instructions | Two distinct system prompts: `SYSTEM_PROMPT` (standard query, full-graph context) and `AGENT_SYSTEM_PROMPT` (tool-calling strategy instructions). LLM tests marked `@pytest.mark.llm` for opt-in execution. | `tests/` directory, `pytest.ini`, `tests/README.md` |
| **9. Observability & Monitoring** | Track system health, performance, cost, and quality in production | `/metrics` endpoint: query counts by type, avg latency, token usage (input/cached/output), cache hit rate, estimated cost in USD, error count, model routing distribution.
